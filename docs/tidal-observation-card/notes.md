# 潮汐观测卡注意事项

## 服务端与客户端

服务器和玩家应使用同版本模组。服务器环境下，配置以服务端为准；客户端本地配置不会决定服务器奖励池、成本、页数或刷新规则。

## 旧配置升级

新版本新增字段时，旧配置通常会使用默认值兜底。旧配置文件不会自动补全文本注释和新字段。

当前刷新配置已经收口到 `trsset.json5` 的 `refresh` 段：

- 旧 `tidal_levels.json5` 里保留 `refresh_hour` / `refresh_minute` 不会导致崩溃。
- 新版本不再推荐继续使用 `tidal_levels.json5` 配置刷新时间。
- 旧 `trsset.json5` 没有 `refresh.hour` / `refresh.minute` 时，会使用默认值 `7:00`。
- 旧 `refresh.mode = fixed_daily` 仍可使用，行为等同于 `world_daily`。

如果服务器管理员希望完整查看新配置项，可以：

- 备份旧配置。
- 删除对应旧配置文件。
- 启动服务器生成新默认配置。
- 再把旧配置中的自定义内容迁移回去。

## 刷新模式选择

`world_daily` 使用 Minecraft 世界时间。单人世界关闭后，世界时间不会继续走，因此第二天现实时间上线不一定刷新。

如果希望离线期间也按现实时间计算，建议使用：

```json
"refresh": {
  "mode": "real_daily",
  "hour": 6,
  "minute": 0
}
```

如果希望每隔固定现实时间刷新，建议使用：

```json
"refresh": {
  "mode": "interval",
  "interval_minutes": 2880
}
```

## 页数调整

`cards.page_count` 增加时，玩家数据会扩展新卡位。

不建议在已经开服后随意降低页数。降低页数可能导致额外页数据在后续保存中不再保留。

## 权重理解

奖励池权重不是百分比。实际概率取决于同一池内所有有效条目的权重总和。

如果一个低权重奖励仍然频繁出现，先确认同池是否有足够多的高权重有效条目，以及是否存在无效条目被过滤。

## 配置错误

常见错误包括：

- 物品 ID 不完整或不存在。
- 标签路径不存在。
- `count_min` 大于 `count_max`。
- `price_min` 大于 `price_max`。
- 权重小于等于 0。
- 组件格式不符合当前 Minecraft 版本。

建议修改后使用 `/trs doctor` 检查，并查看 `latest.log`。
