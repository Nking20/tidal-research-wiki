# 潮汐观测卡注意事项

## 服务端与客户端

服务器和玩家必须使用同版本模组。服务器环境下，配置以服务端为准；客户端本地配置不会决定服务器奖励池、成本、页数、刷新规则或河神结果。

1.0.28修改了观测界面、卡牌更新和轮转网络数据，并新增河神网络数据。1.0.24与1.0.28不能跨版本联机，应同时更新客户端和服务端。

## 旧配置升级

新版本新增字段时，旧配置通常会使用默认值兜底。旧配置文件不会自动补全文本注释和新字段。

当前刷新配置已经收口到 `trsset.json5` 的 `refresh` 段：

- 旧 `tidal_levels.json5` 里保留 `refresh_hour` / `refresh_minute` 不会导致崩溃。
- 新版本不再推荐继续使用 `tidal_levels.json5` 配置刷新时间。
- 旧 `trsset.json5` 没有 `refresh.hour` / `refresh.minute` 时，会使用默认值 `7:00`。
- 旧 `refresh.mode = fixed_daily` 仍可使用，行为等同于 `world_daily`。

如果服务器管理员希望完整查看新配置项，可以：

- 备份旧配置。
- 删除对应旧配置文件。
- 启动服务器生成新默认配置。
- 再把旧配置中的自定义内容迁移回去。

## 从1.0.24升级

1.0.24已有原始潮汐轮转，但没有持久化潮汐值、浅潮/回潮/深潮三档模式、可视化配置编辑器、漂流瓶和河神。

升级到1.0.28时：

- 原有观测卡、观测代券、兑换代券和轮转代券注册ID会保留。
- 原有玩家卡牌数据会继续读取。
- 新增潮汐值和河神统计从默认值开始。
- 已持有的旧轮转代券不会消失，可以右键转换为一份浅潮所需的潮汐值。
- 新奖励流程不会继续产出轮转代券。
- 建议升级前备份世界与 `config/trs/`。

旧 `tidal_spin.json5` 可以继续读取缺失字段的默认值，但不会自动写入新的 `progress` 和 `modes` 注释。希望完整调整三档轮转时，建议备份后重新生成配置。

## 潮汐值分段

潮汐值不是所有等级都能无条件积满：

- I～II级操作只能填充第一段。
- III～IV级操作最多填充第二段。
- V级操作才能填充第三段。

如果玩家无法继续增加潮汐值，先检查当前操作等级对应的分段上限，而不是直接判断配置失效。

## 漂流瓶状态

使用漂流瓶后，保证触发状态会保存在玩家数据中，并在死亡后复制到新玩家实体。玩家退出再进入不会通过重复使用漂流瓶叠加多次保证触发。

河神界面打开时，原钓鱼掉落由服务端暂存，必须完成一次选择才能正常结算。正式服务器不建议在玩家选择期间强制关闭进程。

## 可视化编辑器

`/trs config` 会直接修改服务端 `tidal_pools.json5` 并重载配置。建议注意：

- 只有权限等级2的玩家可以打开。
- 当前只编辑正常观测奖励池，不编辑放弃池、轮转配置或河神奖励池。
- 高级物品数据可以通过主手或背包映射保留，但界面中只支持整体复制、保存或删除，不适合手工编辑复杂组件。
- 大规模调整前仍应备份原配置文件。

## 刷新模式选择

`world_daily` 使用 Minecraft 世界时间。单人世界关闭后，世界时间不会继续走，因此第二天现实时间上线不一定刷新。

如果希望离线期间也按现实时间计算，建议使用：

```json
"refresh": {
  "mode": "real_daily",
  "hour": 6,
  "minute": 0
}
```

如果希望每隔固定现实时间刷新，建议使用：

```json
"refresh": {
  "mode": "interval",
  "interval_minutes": 2880
}
```

## 页数调整

`cards.page_count` 增加时，玩家数据会扩展新卡位。

不建议在已经开服后随意降低页数。降低页数可能导致额外页数据在后续保存中不再保留。

## 权重理解

奖励池权重不是百分比。实际概率取决于同一池内所有有效条目的权重总和。

如果一个低权重奖励仍然频繁出现，先确认同池是否有足够多的高权重有效条目，以及是否存在无效条目被过滤。

## 配置错误

常见错误包括：

- 物品 ID 不完整或不存在。
- 标签路径不存在。
- `count_min` 大于 `count_max`。
- `price_min` 大于 `price_max`。
- 权重小于等于 0。
- 组件格式不符合当前 Minecraft 版本。

建议修改后使用 `/trs doctor` 检查，并查看 `latest.log`。
