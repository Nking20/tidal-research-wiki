# 制作连续任务线

任务线用来把一组委托整理成玩家可查看的故事或进度列表。它不另外保存一套解锁规则：先后顺序仍由每份委托的前置委托和出现方式决定。

## 先准备委托

先确保要使用的委托已经能正常接取、提交和领奖。创建连续剧情时，建议把各章节的重复模式设为“仅一次”，避免已完成的旧章节重新进入抽取池。

## 建立任务线

1. 以二级管理员身份执行 `/tc editor manage`。
2. 打开“任务线”分页，点击“新建任务线”。
3. 填写任务线 ID、名称、描述和图标。ID 发布后应保持不变。
4. 在右侧搜索已有委托，将需要的委托加入任务线。
5. 保存后，玩家可从委托板的任务线入口查看描述、进度和每份委托的当前状态。

任务线编辑器只管理名称、图标和成员。要设定顺序，在成员右侧点击“编辑”，进入该委托的“条件”页设置前置委托和出现方式。“查看委托关系”可用于核对直接前置和直接后续。

## 两种出现方式

| 选项 | 前置全部完成后的行为 |
| --- | --- |
| 进入随机池 | 只是获得抽取资格，仍按档位、来源和权重正常抽取。 |
| 优先出现 | 进入后续队列，有普通空闲栏位时直接翻开；栏位已满时等待，不会挤掉现有委托。 |

两种方式都不会自动接取委托。阶段条件、重复限制等其他资格判断仍然生效。

## 示例：船坞重启计划

内置示例使用六份现有船坞委托：

```text
船板供应 ─→ 传动机构 ─→ 锚链生产 ─┐
                                      ├─→ 船体总装
索具供应 ─→ 船帆布料 ───────────┘
```

- “传动机构”在完成船板供应后进入随机池。
- “船帆布料”在完成索具供应后进入随机池。
- “锚链生产”在传动机构完成后优先出现。
- “船体总装”有两个前置，只有船帆布料和锚链生产都完成后才能进入随机池。

多个前置始终表示“全部完成”。如果想让两条分支可同时出现，让它们共用同一个已完成前置；不要把两条分支互相设为前置。

## 用 JSON 定义任务线

服务端从 `config/tidalcommission/task_lines/` 读取任务线：

```json
{
  "id": "my_pack:harbor_recovery",
  "title": "港口复工",
  "description": "补齐码头材料，修复设备，让第一艘货船重新出港。",
  "icon": "minecraft:oak_boat",
  "tasks": [
    "my_pack:harbor_materials",
    "my_pack:harbor_repairs",
    "my_pack:harbor_departure"
  ]
}
```

`tasks` 只是任务线的展示列表。仍需要在 `harbor_repairs` 和 `harbor_departure` 的任务 JSON 中分别填写 `prerequisites` 和 `unlock_mode`。修改后执行 `/tc reload`。

## 验收

1. 用没有相关完成记录的玩家测试。
2. 执行 `/tc doctor`，确认没有缺失、自引用或循环前置。
3. 正常抽取并完成起始委托，不要用“测试”按钮验证解锁，因为它会绕过抽取资格。
4. 将普通栏位占满，确认优先后续显示为“等待空闲栏位”；腾出栏位后应自动出现。
5. 在玩家任务线页面确认完成数和每个节点的状态。
