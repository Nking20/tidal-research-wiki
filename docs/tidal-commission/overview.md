# 潮汐委托

潮汐委托是一个围绕“委托板”展开的任务型模组。玩家通过潮汐委托板翻开委托卡，支付接取成本，提交指定物品后获得奖励。委托分为多个来源和三个档位，服务器和整合包作者可以通过配置与数据包扩展委托内容。

## 当前功能

- 潮汐委托板
- 五个委托栏位
- 三个委托档位
- 官方、民间、灰色组织等默认来源
- 可配置来源权重
- 可配置指定来源栏位
- 数据包/KubeJS 委托注入
- 灰色组织随机奖励池
- 玩家自定义委托
- 调度令
- 担保凭证
- Curios 可选联动
- 服务端配置同步

## 物品

### 潮汐委托板

注册名：

```text
tidalcommission:commission_board
```

用途：

- 右键打开潮汐委托界面。
- 背包中持有时，可用快捷键打开界面。
- 安装 Curios 时，放入 Curios 栏位后也可用快捷键打开。
- 默认首次进入世界会自动给予一个潮汐委托板，可在配置中关闭。

合成配方：

```text
PPP
SCS
PWP
```

材料：

| 字符 | 材料 |
| --- | --- |
| `P` | 纸 |
| `S` | 木棍 |
| `C` | 指南针 |
| `W` | 橡木木板 |

### 调度令

注册名：

```text
tidalcommission:dispatch_token
```

用途：

- 右键使用。
- 需要玩家身上有潮汐委托板，背包或 Curios 饰品栏均可。
- 会查找当前委托板中剩余时间最长的惩罚或完成冷却栏位。
- 成功后刷新该栏位，使其重新变为可翻开的灰卡。
- 非创造模式下成功使用会消耗 1 个调度令。
- 默认内置使用冷却为 5 秒，可配置。

注意：

- 当前默认没有配方，适合由整合包作者或服务器自行配置获取方式。
- 没有可刷新目标时不会消耗。

### 担保凭证

注册名：

```text
tidalcommission:guarantee_voucher
```

用途：

- 接取普通委托时优先消耗。
- 可替代“接取成本”。
- 不替代翻开卡牌的成本。
- 不替代提交任务所需物品。
- 非创造模式下接取成功后消耗 1 个。

注意：

- 当前默认没有配方，适合整合包作者或服务器自行配置获取方式。

## 基础玩法

1. 获得潮汐委托板。
2. 右键打开，或按快捷键打开。
3. 选择一个灰卡栏位。
4. 选择档位。
5. 支付翻开成本。
6. 查看委托内容。
7. 选择接受或放弃。
8. 接受后委托进入进行中状态。
9. 准备并提交需求物品。
10. 完成后获得奖励并进入冷却。

## 快捷键

默认快捷键：

```text
R
```

功能：

- 背包或 Curios 中有潮汐委托板时，按 R 打开潮汐委托界面。
- 潮汐委托主界面、详情界面、管理任务界面已打开时，按 R 关闭界面。
- 在背包界面或创造模式背包界面中也允许使用 R 打开。

## 委托栏位

当前委托板有 5 个栏位。

栏位状态：

| 状态 | 说明 |
| --- | --- |
| 灰卡 | 未翻开，可选择档位并翻开 |
| 白卡 | 已翻开，显示可接受委托 |
| 进行中 | 已接受，显示剩余时间和详情/放弃按钮 |
| 惩罚 | 放弃或过期后进入惩罚等待 |
| 冷却 | 完成后进入冷却等待 |

## 默认来源

| 来源 ID | 默认显示 | 默认权重 | 是否启用 | 说明 |
| --- | --- | ---: | --- | --- |
| `official` | Official / 官方 | 40 | 是 | 官方委托 |
| `folk` | Folk / 民间 | 40 | 是 | 民间委托 |
| `gray` | Gray Organization / 灰色组织 | 20 | 是 | 奖励隐藏，完成后从灰色奖励池随机结算 |
| `shipyard` | 造船企业模板来源 | 0 或按配置 | 视配置 | 内置示例来源，可供整合包作者参考 |

权重计算方式：

```text
单个来源权重 / 所有可用来源权重总和
```

权重总和不必等于 100。

## 默认任务数量

当前内置任务总数：60 个。

| 来源 | 一档 | 二档 | 三档 | 合计 |
| --- | ---: | ---: | ---: | ---: |
| `official` | 7 | 8 | 7 | 22 |
| `folk` | 8 | 8 | 6 | 22 |
| `gray` | 4 | 3 | 3 | 10 |
| `shipyard` | 2 | 2 | 2 | 6 |

## 玩家自定义委托

入口：

- 主界面右下角“Custom Commission / 自定义委托”。
- 管理入口为“Manage Tasks / 管理任务”。

规则：

- 玩家只能从当前配置中已启用的来源里选择。
- 需求目前只支持物品。
- 奖励来自发布者背包中的真实物品。
- 发布成功后奖励会从发布者背包中扣除并保存在世界数据里。
- 发布者不能完成自己的自定义委托。
- 如果委托过期，奖励会退回发布者。
- 如果委托尚无人接取，发布者可以在管理界面取消。
- 如果已经有人接取，当前逻辑不允许取消。
- 如果有人完成该委托，奖励发给完成者。
- 如果启用广播，完成时全服提示。
- 如果一个玩家完成了某个玩家委托，其他接了同一委托的玩家对应栏位会进入完成冷却。
- 如果接取人数达到上限，其他玩家已翻出的同一委托会失效并进入冷却。

## 配置文件

配置目录：

```text
config/tidalcommission/
```

主要配置文件：

| 文件 | 用途 |
| --- | --- |
| `commission_rules.json` | 基础时间、翻卡成本、来源、指定栏位、调度令冷却、首次进服给予委托板 |
| `gray_reward_pools.json` | 灰色组织任务完成后的随机奖励池 |
| `player_commissions.json` | 玩家自定义委托开关、上限、过期时间、奖励槽位和广播 |

### commission_rules.json 核心字段

| 字段 | 说明 |
| --- | --- |
| `timing.task_duration_days` | 接取后限时 |
| `timing.abandon_penalty_days` | 放弃委托后的惩罚时间 |
| `timing.expired_penalty_days` | 委托超时后的惩罚时间 |
| `timing.completion_cooldown_days` | 完成委托后的冷却时间 |
| `open_costs` | 翻开不同档位卡牌的成本 |
| `directed_slots` | 指定来源栏位 |
| `items.dispatch_token.use_cooldown_seconds` | 调度令使用冷却 |
| `items.starter_items.give_commission_board_on_first_join` | 首次进入世界是否自动给予委托板 |
| `sources` | 委托来源列表 |

指定来源栏位示例：

```json
"directed_slots": [
  {
    "enabled": true,
    "slot": 5,
    "cost_multiplier": 1.5
  }
]
```

### gray_reward_pools.json

灰色组织任务在界面中显示奖励为未知。完成后从对应档位的奖励池随机结算。

```json
{
  "config_version": 2,
  "gray_rewards": {
    "tier_1": [
      {
        "weight": 10,
        "primary": {
          "item": "minecraft:gold_ingot",
          "count": [8, 10]
        },
        "extras": []
      }
    ]
  }
}
```

### player_commissions.json

```json
{
  "enabled": true,
  "max_open_per_player": 5,
  "expire_days": 7.0,
  "reward_slots": 6,
  "max_requirement_count": 999,
  "default_max_accepts": 1,
  "max_accepts_limit": 8,
  "player_commission_pick_weight": 2,
  "broadcast_completion": true
}
```
