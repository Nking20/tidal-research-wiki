# 潮汐委托

潮汐委托是一个面向整合包作者的服务端权威委托系统：玩家翻开并接取委托，在限时内完成交付、清剿、探索等目标，再领取固定或可选奖励。任务来源、目标、权重、冷却、阶段条件与玩家委托均由服务端决定。

## 1.6.0 更新重点

- **自动补充委托**：服务器可定期把新委托放入空闲栏位。自动补充只免去翻开栏位的费用，接取成本仍由委托自身决定。
- **等待接取时限**：已出现但未接取的委托会显示接受倒计时，过期后释放栏位，避免长期占用任务池。
- **接取后无期限任务**：任务 JSON 的 `duration` 为 `0` 时，委托仍需按时接取，但接取成功后不限制完成时间。
- **委托追踪 HUD**：最多追踪三份进行中的委托，并显示简介、目标进度和剩余时间。
- **任务日志**：记录已经成功、失败或放弃的委托，以及结束时的游戏日。
- **游戏内配置中心**：通过 `/tc config` 调整本地界面和服务器规则；非管理员只能查看服务器设置。
- **完成与新委托提示**：自动目标达成或新委托送达时，会在右上角显示简短提示。
- **玩家委托界面重做**：发布流程分为基本信息、需求与奖励、预览发布三步，并重新整理管理页。

完整实现与验证情况见 [1.6.0 当前状态](./status.md)。

## 主要内容

- 五个独立状态的委托栏位，以及可选的指定来源栏位。
- 官方、民间、灰色组织等可配置来源；整合包也可新增来源。
- 数据驱动任务、可视化任务编辑器和来源分类编辑器。
- 多目标组合、分批交付、组件匹配、可选奖励、重复规则和前置任务。
- 自动委托轮换、等待接取期限和接取后无期限任务。
- 可配置的委托追踪 HUD、右上角提示与历史任务日志。
- 调度令、担保凭证与委托总集。
- 可选的玩家自定义委托。
- 静态任务支持数据包初始化、配置文件维护，以及 KubeJS 阶段驱动。

## 服务端规则

联机环境以服务端 `config/tidalcommission/` 和服务端数据包为准。客户端本地配置不决定任务抽取、来源权重、阶段、冷却或玩家委托。

修改任务后，推荐执行：

```text
/tc reload
/tc doctor
```
