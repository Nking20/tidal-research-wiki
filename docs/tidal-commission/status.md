# 1.5.0 当前开发状态

潮汐委托 1.5.0 目前处于开发测试阶段，版本号已经确定，但尚未作为正式版发布。本文记录的是当前代码中已经实现的内容，以及发布前仍需验证的部分。

## 已经实现

- **多入口打开委托**：可通过背包底部页签、快捷键、`/tc open`、委托板物品或其他模组调用的接口打开。
- **可配置访问规则**：支持始终可用、必须持有委托板、持有一次后永久解锁、仅允许外部入口四种模式。
- **复合目标**：一项委托可以包含多个目标，并设置为全部完成、任意一项或至少完成指定数量。
- **更多目标类型**：内置物品、物品标签、击杀实体和到达群系；代码接口允许兼容模组注册新的目标类型。
- **组件匹配**：物品目标可按物品本身、包含指定组件或完全一致的组件匹配，用于区分药水、酒类等同物品 ID 不同数据的物品。
- **三种交付方式**：提交并消耗、只检查不消耗、分批存入。
- **奖励方案**：委托可以只有固定奖励、只有可选奖励，或同时提供两者；每个可选方案也可包含多项奖励。
- **前置与重复规则**：支持前置委托、仅一次、冷却、每日和每周等限制。
- **来源分类管理**：游戏内编辑器可维护官方、民间、灰色组织等大类的名称、权重、状态、颜色和图标，也可新增或删除未被任务引用的来源。
- **可视化任务编辑器**：新目标、组合规则、交付方式、组件匹配、奖励方案、重复规则和前置委托均已接入编辑流程。
- **默认演示委托**：已加入多目标、标签、组件匹配、击杀、群系、纯可选奖励、每日前置等示例，方便整合包作者直接查看效果。
- **物品栏底部页签兼容**：潮汐委托已经接入与其他潮汐模组共用的底部页签布局；Curios 联动暂时保留。

## 已完成的修复与验证

- 修复多击杀目标之间进度相互覆盖的问题；每个目标现在独立保存进度。
- 多目标进度经过保存与重新读取后仍能保留。
- 目标组合规则已有单元测试覆盖。
- 当前开发代码已通过 Gradle 测试与构建，并完成过 NeoForge 1.21.1 客户端启动检查。

## 发布前仍需重点测试

- 多人服务器中的多目标同步、掉线重连和跨维度行为。
- 可选奖励在背包空间不足、多人同时结算等情况下的完整流程。
- 每日、每周、冷却和前置委托在长时间存档中的边界情况。
- 物品组件匹配与不同模组自定义物品数据的兼容性。
- 潮汐委托、辑录与揭秘、潮汐观测卡同时安装时的底部页签点击与排列。
- 游戏内编辑器对旧 1.3.0/1.4.0 配置的读取、保存与热重载。

因此，1.5.0 当前适合整合包作者测试和反馈，但还不应在没有回归测试的情况下标记为稳定正式版。
