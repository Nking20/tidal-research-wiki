# 炼狱安装、配置与兼容

## 安装关系

炼狱培育 **0.4.4-alpha** 面向 Minecraft 1.21.1 NeoForge，需要相容的潮汐培育，当前工程最低核心版本为 **1.0.4-alpha**，并使用 Java 21 与 GeckoLib

炼狱不是独立的第二套档案系统，客户端与服务端都需要对应模组和依赖，替换时不要残留同模组的旧 JAR

## 配置

炼狱温控、食物、分裂与蜕壳参数使用服务端配置

- 单人：`saves/<世界>/serverconfig/infernalnursery-server.toml`
- 独立服务器：`<世界目录>/serverconfig/infernalnursery-server.toml`
- 新世界默认值可通过整合包的 `defaultconfigs` 准备

实际世界目录可由服务器设置更改，服务端配置由服务器决定，修改客户端本地副本不会覆盖远程世界规则

默认环境扫描约 10 秒，温标为 -100～+100，调整最佳区间、介质系数或事件周期后，Wiki 默认数字不再代表该整合包

## 基因拓展

基础两组仍为体型 / 韧性、代谢 / 产能，拓展组为耐温 / 炼狱环境亲和

四种物种均注册到核心物种目录和 `infernalnursery:thermal` 拓展，采集、记录、档案、删除和重构继续由核心处理

档案按物种隔离，水母的拓展组合不能写入炽足兽，同为炼狱样本也不能跨物种套用组合

耐温扩展冷热边界，环境亲和调节自然与人工温控响应，实际效果在熔育槽详情里查看

## 保存与搬运

熔育槽保存样本、介质和物种事件状态，细雪有独立保存字段，正常读档不把它替换成水

新槽为空，搬运物品恢复自己保存的介质，不因合成材料中有培育皿就继承新皿的初始水量

旧菌食物品继续兼容，未知基因或缺失物种不能靠清空数据恢复，升级前保留世界和旧 JAR

移除炼狱会使注册内容缺失，不要在有其物品、实体或档案的世界里把卸载当作回退方案

## 排查

| 现象 | 检查 |
| --- | --- |
| 温度不变 | 等待扫描，悬停温度计看实际来源 |
| 配件无法放入 | 是否同时装了加热和制冷，是否为支持的槽位 |
| 霜烬螈休眠 | 温度是否过热，是否缺食，先处理显示原因 |
| 梳毛或凝露不动 | 是否成年、恢复中，温度和健康饱食是否合格 |
| 分裂不动 | 健康 80、饱食 70、无护理需求等条件是否满足 |
| 蜕壳没出完整甲壳 | 完整甲壳需要完美结果，检查本轮照料与蜕缝处理 |
| 无法采样 | 是否最小岩浆怪、变冷炽足兽或对应临时状态，是否已经采过 |

报告问题时保留两个模组版本、旧存档来源和日志，文档更新不代表已完成所有公开服务器或整合包的兼容测试
